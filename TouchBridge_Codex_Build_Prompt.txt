# TouchBridge — Codex implementation brief

You are Codex, acting as a senior native Android engineer and an effective pair programmer. Build a real, runnable Android application called **TouchBridge**: an NFC-initiated peer-to-peer sharing app for **two Android phones**. I want actual implementation, tests, build instructions, and an installable debug APK if this environment can produce one—not just a concept, outline, design mockup, or pseudo-code.

- Test device B: **Samsung Galaxy S21 Ultra**, Android version not yet confirmed. Detect the runtime API level and handle differences gracefully; do not assume it's on Android 17.

Use the checked-in Gradle Wrapper, standard Android SDK tooling, portable configuration, and documented PowerShell/Windows + Bash/Linux commands. Do not hard-code a developer machine path or assume an operating system in app logic.

## 2. Product vision

The long-term goal is a customizable **touch-to-share** Android experience: open the app on two phones, choose compatible NFC modes, touch the phones together, pair using the brief NFC encounter, move the phones apart, and transfer content through a faster secure local connection. Eventually support files, photos, text, links, contact cards, Wi-Fi access details (where legitimately possible), and playful extras such as shared sessions or game pairing.

**Important realism:** Android Beam's old phone-to-phone push functionality is deprecated; ordinary apps cannot replace the system Quick Share/NameDrop interaction or guarantee background activation from arbitrary locked/home screens. The viable custom NFC path is **one phone using Host Card Emulation (HCE)** and **the other using reader mode**, communicating over ISO-DEP/APDU. HCE is not universal NDEF peer-to-peer push. Use NFC for a tiny handshake, not for large files. Make limitations visible in the UI and README.

## 3. Technology requirements

- **Native Android, Kotlin, Jetpack Compose, Material 3.** Single Android app installed on both devices.
- Use current *stable, mutually compatible* Kotlin, Android Gradle Plugin, Compose BOM, AndroidX, and Google Play Services Nearby dependencies. Check installed SDK/toolchain and official docs before selecting versions; never invent version strings.
- Use `NfcAdapter`, `enableReaderMode()`, `IsoDep` for the reader and `HostApduService` for the emulator. Declare HCE properly in the manifest and `res/xml` with `android.permission.BIND_NFC_SERVICE`, the HCE intent filter, and a **unique non-payment proprietary AID** in category `other`. Never register as a payment service or interfere with the default wallet.
- Use **Google Nearby Connections** for offline peer discovery, encrypted connections, text/byte messages, and large file payloads. Consider `Strategy.P2P_POINT_TO_POINT` for the first implementation. Clearly report when Google Play Services is unavailable.
- Use coroutines / `StateFlow`, a small repository or coordinator abstraction, a ViewModel for UI state, and a clear transport boundary so NFC, Nearby, and sharing features can be tested independently.
- Use the Storage Access Framework (`ACTION_OPEN_DOCUMENT`, `ACTION_CREATE_DOCUMENT`, or equivalent Activity Result contracts) / `content://` URIs for user-controlled files. Do not request all-files access or broad storage permissions unless truly necessary.
- No backend, server, account system, internet connection, cloud storage, analytics, or advertising. Nearby Connections may depend on installed Google Play Services but transfers must not rely on a WAN connection.

## 4. UX and interaction design

Make the main app visually clean and modern with a minimal, thoughtful Material 3 UI. Suggested top-level actions:

- **Send** — choose a file, image, text, or link, then start pairing.
- **Receive** — wait for another phone.
- **NFC Lab** — test HCE/reader exchange and see useful technical feedback.
- **History** — optional, with no sensitive data stored by default.
- **Settings / About** — capabilities and troubleshooting information.

Use plain language on screen ("Hold phones together", "Connected", "Accept transfer") with a collapsible diagnostics screen showing role, NFC capability, Android API version, Nearby state, connection step, and sanitized errors. Start with an explicit role selection for reliable testing: **Emulate / Advertise** on one phone; **Scan / Discover** on the other. Later, design a symmetric experience without assuming two readers can exchange APDUs directly. Both devices should eventually be able to switch roles.

Preserve usable UI when NFC is disabled or absent; offer a button opening the appropriate system settings. Add permission rationale screens and a no-NFC discovery fallback if practical after the NFC MVP.

## 5. Milestones: build working software in this order

### Milestone 0 — runnable project (Windows development first)

Create the complete Android project with Gradle wrapper, proper manifest, Compose navigation/UI, capability checks (`FEATURE_NFC`, `FEATURE_NFC_HOST_CARD_EMULATION`), a readable README, and a sensible folder structure. **Compile and run unit tests on Windows before declaring this milestone complete**, if the SDK/build environment is available. ### Milestone 1 — real phone-to-phone NFC handshake (FIRST NONNEGOTIABLE WORKING DEMO)

Implement both roles in the *same app*:

**HCE phone:**
- Start a short-lived sharing session only when the user explicitly enters the HCE/advertise screen.
- Create a cryptographically random, short-lived session identifier (e.g. 128-bit random ID); do not use hardware IDs or personal identifiers.
- Expose a `HostApduService` with the proper manifest and AID XML.
- Implement an APDU `SELECT AID` command and a separately defined `GET_SESSION` command. Return correctly encoded response APDUs and ISO-7816 status words, including error paths.
- Return the protocol version, session ID, and optional coarse capabilities; keep the entire exchange short. Validate APDU framing, bound payload sizes, expire the session, and return safe errors if idle.
- `processCommandApdu()` must not do blocking work on the main thread. Establish safe communication between the service and session coordinator.

**Reader phone:**
- Enable reader mode while the scan screen is foregrounded (`NfcAdapter.enableReaderMode`), preferring NFC-A/ISO-DEP, and disable it on pause.
- On tag discovery, check `IsoDep`, connect, issue `SELECT AID`, verify status word `0x9000`, send `GET_SESSION`, parse and validate version/length/session/expiry, then close the connection.
- Handle `TagLostException`, unsupported tech, wallet interference, NFC disabled, malformed APDU responses, duplicate tag callbacks, and timeout. Perform transceive off the UI thread.
- Show **"NFC handshake successful"**, the peer/session info in a privacy-preserving way, and the elapsed time. Make the simplest demo a genuine APDU exchange, not mock NFC.
- Write unit tests for APDU encoding/decoding, protocol validation, expiry, and state transitions.

**Acceptance:** Pixel and S21 Ultra, with the app installed on both and their screens unlocked, can each take turns as reader vs emulator. Touching the appropriate NFC antenna areas results in a real successful handshake without any network or file-transfer layer. **Until I perform physical phone tests on Arch Linux, mark this milestone as "implemented/build-checked; hardware validation pending," not as verified.**

### Milestone 2 — Nearby connection bootstrapped from NFC

- The HCE device starts Nearby **advertising** for its current session when the user enters advertise mode. The reader device starts **discovery** after a valid NFC handshake. Map the ephemeral NFC session ID to the advertising endpoint (e.g. public ephemeral session ID in endpoint name or another documented discovery field); don't invent an API for directly connecting via NFC to a Nearby endpoint ID.
- Apply accurate Google Play Services Nearby permissions and runtime requests for API levels on both phones. Include Android 12+ Bluetooth permissions, Android 13+ nearby Wi-Fi permission, and Android 17 local-network permission only where the API/target/transport rules require it. Use current official documentation, not a blanket permission grab.
- On discovery, connect only to the endpoint correlated with the NFC session. Implement Nearby `ConnectionLifecycleCallback` + `EndpointDiscoveryCallback`, statuses, cancellation, timeouts, reconnection after failed attempts, and proper stop advertising/discovery lifecycle cleanup.
- Require both devices to **accept the connection**, and show Nearby's **authentication digits/verification code** to prevent a nearby attacker impersonating the device. Never equate "NFC was touched" with unlimited trust. Reject unverified peers and expired sessions.
- Send one small message ("Hello from the other phone") after an authenticated connection, with an explicit accept action. Display receipt on the other device.
- Never silently start unapproved data transfers or install apps.

**Acceptance:** With both devices using the app, a tap starts a correctly matched, user-approved Nearby session. After moving phones apart, a small text message arrives. No internet required.

### Milestone 3 — real file transfer

- Integrate Android Sharesheet receiving (`ACTION_SEND` and `ACTION_SEND_MULTIPLE`) and in-app file/document picking.
- Transfer text/link via `Payload.Type.BYTES`; use Nearby `Payload.Type.FILE` for files, without reading entire large files into RAM.
- Send file metadata (sanitized filename, MIME type, byte length if known, payload ID association) through an authenticated channel before or alongside binary payload; handle out-of-order arrival correctly.
- Show file name, transfer size, progress, sending/receiving/success/error, cancel button, and save confirmation.
- Use `ContentResolver` / descriptors and `MediaStore` or Storage Access Framework for safe writes. Preserve the correct MIME type, handle Android scoped storage and URI grants. Never trust raw remote file paths; prevent path traversal. Avoid overwriting files silently.
- Handle rejection, disconnect during transfer, partial files, 0-byte and large files, duplicates, and payload status updates.

**Acceptance:** Transfer one image and one PDF, then a larger video, from Pixel to Samsung and vice versa. The resulting files open correctly and are identical where practical (hash comparison for tests).

### Milestone 4 — extra sharing modes

- Clipboard-like text: explicitly paste or share selected text; don't promise unrestricted background clipboard monitoring.
- Links: transfer an ordinary URL and offer to copy/open with a safe Android intent; don't auto-open potentially unsafe content.
- Contacts: export/import a selected vCard with proper Contacts/SAF system flow and consent; don't read the entire contact database.
- Wi-Fi: ordinary third-party apps generally **cannot retrieve stored Wi-Fi passwords** or silently join arbitrary saved networks. Provide a **manual SSID/security/password input** or appropriate OS-supported Wi-Fi share flow. Require explicit sender confirmation; do not persist credentials or include them in logs/analytics. On receiver, present a protected, consent-driven view with a copy action or system-supported QR/network-join approach where available; do not pretend Wi-Fi Easy Connect universally permits phone-to-phone saved password extraction.
- Optional: multiple file selection, device nicknames, a non-sensitive recent transfer list, discover-without-NFC fallback.

## 6. Security, platform constraints, and error handling

- NFC handshake conveys short-lived, non-personal pairing metadata, never sensitive plaintext credentials or full files. Sessions expire quickly (e.g. 60 seconds) and are invalidated after cancellation or successful pairing.
- NFC session IDs used for matching are **not authentication secrets** if broadcast in Nearby endpoint metadata. Require Nearby's documented connection authentication and explicit confirmation on both sides.
- UI state should make it obvious when a connection is merely detected vs authenticated vs accepted; prevent sending until approved.
- Keep role and transfer state lifecycle-aware, clean up radios and pending work when cancelled, and don't keep indefinite background services.
- Do not require both devices to remain touching after the NFC handshake.
- NFC antenna alignment varies by device; provide troubleshooting hints.
- Do not claim to support tap-to-launch from a locked phone, replacing system Quick Share, or automatic transfer while both apps are closed. Mark such behaviors as experimental or unsupported unless verified with public APIs on both physical devices.
- Do not include dangerous permissions, hidden APIs, root, full-contact scanning, or undifferentiated personal-data collection.
- Instrument logcat events with feature-specific tags but redact authentication codes, tokens, passwords, content, and filenames unless the user enables an explicit debug-only diagnostic mode.
